# 版本规划

> 本文件是版本总纲；对标依据见 `benchmark-codex-desktop.md` / `benchmark-zcode-desktop.md`，各排期明细见对应排期文档。
> 改代码前先读：`AGENTS.md`（工程导航）→ 本文件 → 对应排期文档。

## 方向（三条，来自重构决策）

1. **只保留聊天形态**——终端形态整体退场，聊天成为唯一形态；
2. **聊天形态对标 Codex Desktop、Zcode Desktop**——样式、布局、流式对话、聊天框；
3. **设置重构**——现有设置功能全量保留，操作方式与展现形式重新设计。

## 版本号与发版约定

- 0.x 系列、语义化版本；`package.json` / `src-tauri/tauri.conf.json` / `src-tauri/Cargo.toml`（+ `Cargo.lock`）四处同步。
- 发版：打 `v*` tag 推送 → `.github/workflows/release.yml` 四平台打包并生成 `latest.json`（应用内更新数据源）。
- `CHANGELOG.md` 按 Keep a Changelog；版本节即 Release 说明（`scripts/changelog-notes.mjs` 抽取，缺失会挡发版）。

## 现状交代（0.1.0 三方向已交付；0.2.0 右栏工作台、会话读数、omp 约束已实施）

- **聊天是唯一形态**：终端形态（PTY + xterm + 工作区树）已按 `v1-schedule.md` 的清单删除，形态切换、终端左栏与标签栏、终端专属文案与字体资产全部退场。
- 形态收敛是**做减法**：聊天形态承接全部有效能力（会话运行 / 流式 / 队列 / 审批 / fork / 归档 / 提交 / 设置面）；项目拖拽排序与「移除项目」入口迁移进聊天左栏。
- 聊天对标是**呈现与交互重做**（数据层不动）：三栏布局（新增右栏上下文面板）、摘要式消息流（命令批 / 编辑卡 / 轮时长行）、输入卡（卡顶行内嵌项目与分支、卡底工具行合并模型与思考档、执行模式菜单）、命令面（会话置顶 + 编号快捷键）、左栏常驻命令行与会话状态标。明细见 `v2-schedule.md`，变更记录见 `CHANGELOG.md` 的 0.1.0 节。
- 设置重构：设置从「页签 + 卡片列表」改为独立视图——**顶部条**（返回 + 当前条目名；2026-10-19 顶部条的搜索钮去除，搜索入口只剩 `⌘F`）+ **四组导航**（通用 / 模型 / 扩展 / 数据）+ **跨条目搜索**（常用设置四档打分、模型 / 插件 / 技能 / 记忆 / 归档命中高亮，结果跳转 + 键名定位闪烁）+ **行式控件**（区块标题 + 分隔线 + 语义行高，页面不做卡片）；七个条目的读写能力全量保留。明细见 `v3-schedule.md`，变更记录见 `CHANGELOG.md` 的 0.1.0 节。
- **右栏工作台（0.2.0）**：右栏从 v2 的「上下文」面板（变更 / 进度 / 子代理 / 来源）换成**文件 / 脚本 / 终端三页签**——文件页签是当前会话工作目录的只读目录树（懒加载、变更标色、系统打开、引用到输入框），脚本页签把项目里能跑的东西摆出来（后端只读识别 `package.json` / `Cargo.toml` / `go.mod` / `manage.py` / `Makefile` / `justfile` / `Taskfile`，加本应用偏好里的自定义脚本），点一下就在终端页签里执行——终端是 PTY 里的登录 shell（真交互、全屏程序可用、按 cwd 保留、收起面板不杀进程）。上下文面板四区块连同它们的组件与 `lib/panelSources.ts` 一并退场（子代理 / 任务清单 / 提交链路的数据层保留，任务清单仍有消息列浮卡、提交仍有输入卡顶行键）。明细与验收见 `v4-schedule.md`，变更记录见 `CHANGELOG.md` 的 `0.2.0` 节。
- **会话读数（0.2.0）**：输入卡底部新增**统计条**（四项、整条靠右）——**会话统计**（轮 / 步 / tok/s；点开：模型用时 / 工具调用用时 / 首发平均 TTFT / 输出速度）、**Token 用量**（缓存命中率；点开：分项与千分位总计）、**上下文占用**（容量环；点开分项）、**供应商用量**（只看全部已配置供应商的限额窗口、条上只有图标与档位配色；点开全部窗口）。数据由后端 `live_stats.rs` 扫该会话 jsonl 聚合，打开拉一次、运行中每 3s 回读；工具行原有的上下文容量环与供应商用量**搬到条上**（同一个数字不出现两次）。明细与验收见 `v5-schedule.md`。
- **omp 约束（0.2.0）**：设置通用组新增「omp 约束」——只编辑 omp 的**全局层**三处：`AGENTS.md`（会话启动注入的上下文）、`RULES.md`（每轮重挂的 sticky 规则）、`rules/*.{md,mdc}`（独立规则，文件名即规则名）。三种文件都**直接编辑整份 Markdown**（含 frontmatter；2026-10-19 去掉表单模式），文本原样保存——未知 frontmatter 字段与注释都不动。写入走 `expectHash` 乐观锁 + 备份 + 原子写；新建 / 删除规则，删除走 `ConfirmDialog` 二次确认。明细与验收见 `v6-schedule.md`。
