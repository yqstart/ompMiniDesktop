# ompMiniDesktop 二十六期（V26）：左栏项目拖拽（排序 + 拖进 / 拖出工作区）

> 基线：V25 已交付（终端「回到最新输出」悬浮键）。
> 用户口径：「左侧项目不支持拖拽排序功能，需要支持拖拽，并且可以把项目拖拽进入工作区，也可以把项目从工作区拖拽出来」。
> 本稿记录交互设计、数据模型、命令面与真实界面实测口径；改左栏拖拽这块前先读它。

## 0. 结论先行

| 项 | 之前（V25） | 现在（V26） |
|---|---|---|
| 左栏项目顺序 | 注册顺序（只能追加在末尾） | **可拖拽排序**（全局顺序 = 覆盖层 `projects` 数组顺序） |
| 项目归属 | 只能走「编辑工作区」对话框勾选 | **拖进工作区 / 拖到「未分组」即改归属**（对话框照旧可用） |
| 命令面 | `update_workspace`（改名 + 成员重设） | 新增 `move_project`（**归属 + 全局顺序一次写**，IPC 69 → 70） |
| 拖拽实现 | — | 壳侧自绘（指针事件 + rAF + DOM 矩形命中），**不引第三方拖拽库** |

## 1. 数据模型：全局顺序唯一，容器只是投影

不新增「组内顺序」字段——**覆盖层 `projects` 的数组顺序就是左栏顺序**：

- 组内渲染顺序 = 全局顺序里 `workspaceId` 命中该组（或未分组）的那些项目（`workspace_views` 的 `projectIds` 同源）；
- 拖拽 = 改被拖项目的 `workspaceId` + 把它挪到目标边界（`overlay.projects` 重排），**一次写完**；
- 空容器落点（落在组头 / 空组提示 / 组内空白）= 容器末尾：目标容器最后一个成员之后；容器里没有别的成员 → 数组末尾（渲染上就是「这个容器里的最后一个」）。

好处：删组 / 改组成员不会留下悬空顺序；协作根计算（`collabContextFor` 用 `projects` 顺序）与「新建终端目标」（组内第一个成员）自动跟随新顺序。

## 2. 交互设计

- **拖柄**：项目头（`ProjectGroup` 折叠头那一行，`data-project-drag`）——指针按下后**移动超过 4px 才开始拖**，原地点击照常折叠（拖完那一下补发的 `click` 被吞掉，不会误触折叠）。会话 / 移除项目按钮不在拖柄内（拖不动）。
- **拖拽中**：源项目行留在原地**压暗**（`opacity-40`），幽灵小卡（`Folder` + 项目名）跟手；`document.body` 禁用文本选择、光标 `grabbing`。
- **落点**：
  - 行内 → 按行内中线判「插到这一行之前 / 之后」（中线 = `min(18, 块高/2)`；块里还挂着目录行时不会把上半段判成「之后」）；
  - 容器（组头 / 空组 / 组的空白）→ 容器末尾；
  - 条与条之间的缝隙（组间距、列表底部留白）→ 归**上方最近**的一条（组之间的缝隙 = 上一组的末尾）；
  - 悬在**被拖项目自己**身上 → 不画线（松开原地不动）；
  - 指针离开列表区（别的面板 / 侧栏头部）→ 无落点，松开即取消。
- **视觉反馈**：零高度包装 + 绝对定位的 2px `accent` 插入线（`DropLine`，**不推挤列表**，拖拽全程不抖）；悬在空容器上时，空态提示条换成虚线落区并在命中时上强调色。
- **取消**：Esc、指针取消、窗口失焦都收掉会话（不发请求）。
- **自动滚动**：贴列表上下缘 28px 时每帧滚 12px（长列表里拖到远处不用先手动滚）。
- **无自定义工作区（平铺）**：没有容器段，落点在平铺列表里照常工作（容器恒为「未分组」）；「未分组」区在**拖拽中即使为空也渲染**——那是「拖出工作区」的落点（文案「拖到这里移出工作区」）。

## 3. 命令面（IPC 69 → 70）

| 命令 | 语义 |
|---|---|
| `move_project { id, workspaceId, order }` | 把 `id` 项目移动到 `workspaceId` 工作区（`null` = 未分组），并按 `order` 重排全局顺序；返回新顺序的项目清单 |

- `order` = **全部项目 id** 的目标顺序：认不得的 id 忽略、缺席的项目按原相对顺序补末尾（`apply_project_order`，单测锁着）——任何输入都不丢项目。
- 校验：项目 / 工作区不存在 → `NOT_FOUND`；写入失败 → `OVERLAY_WRITE`。
- 前端落点判定后先算 `planProjectMove`，**顺序与归属都没变就不发请求**（原地松开 = 零 IPC）。

## 5. 边界（不做）

- 不排工作区段本身的顺序（只排项目；组序仍是创建顺序）——要改组的先后得删了重建（现状口径不变）。
- 不做键盘排序（拖拽是唯一排序入口）；改归属仍可用「编辑工作区」对话框。
- 不引第三方拖拽库（`@dnd-kit` 等）：命中 / 排序规则是纯函数，壳侧自绘能精确控制插入线与取消语义。
- 不改多选、不做跨项目拖动（一次只拖一个项目）。

## 6. 完成口径（已达成）

- 项目行可拖拽排序（平铺 / 组内都生效），顺序落盘（重启保持）。
- 拖进工作区（含空组 / 组内指定位置）与拖出到「未分组」都只改覆盖层归属，**不碰任何文件**；右栏终端范围随之重算（组视图下激活终端按 `selectGroup` 收敛）。
- 原地点击 / Esc / 列表外松开都不产生请求；悬在被拖项目自身上不画线。
- `pnpm check`（typecheck + lint + vitest 301 项 + e2e:ipc **70 命令**双向一致）与 `cargo test --locked`（166 项 + 11 ignored）全绿。

## 7. 实测记录（2026-09-29）

**真实界面核对**（`pnpm build` + `vite preview` + Chromium 注入 `__TAURI_INTERNALS__` mock；拖拽用 CDP 真实指针事件，mock 记录 `move_project` 入参）：

| 场景 | 结果 |
|---|---|
| 未分组的 `infra` → 空组「数据平台」组头 | `move_project {id:"p-infra", workspaceId:"w2", order:[fe,be,docs,infra]}`；拖拽中幽灵跟手、空组提示条上强调色（截图核对） |
| `w1` 的 `frontend` → 未分组最后一行下半段 | 插入线在未分组末尾（`END`）；`{workspaceId:null, order:[be,docs,infra,fe]}`；`w1 → [be]`、未分组 → `[docs, fe]` |
| 未分组同容器重排（`frontend` → `docs` 上半段） | 插入线指向 `docs`；结果 `[fe, docs, be]` |
| 拖进空组（= 末尾）后再组内中间插入 | 第一次：容器末尾线（`w1:p-be`）→ `[fe, docs, be]`；第二次：线 `w1:p-docs` → `[fe, be, docs]` |
| 悬在被拖项目自己身上 / Esc 取消 | 均不画线、不发请求（`move_project` 计数不变）；Esc 后幽灵消失 |
| 原地点击项目头（按下即松开） | 不发请求，`aria-expanded` 照常 true → false（拖拽不抢点击） |
| 平铺模式（无工作区，3 个项目） | 无容器段；插到 `beta` 之前的线 + 列表底部留白 = 末尾（`END`）；两次 `move_project` 的 `workspaceId` 均为 `null` |
| 未分组区为空时拖出工作区 | 拖拽中该区临时出现、提示条「拖到这里移出工作区」上强调色；松手 → `{workspaceId:null}`，未分组 → `[fe]` |
